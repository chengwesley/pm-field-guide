# 03 商業模式

> 一句話：說清楚「誰付錢、為什麼付、付多少、我們每賺一塊要花多少」，並確認這門生意算得過來。

## 何時用

- 新產品或新方案要上市，要決定收費方式（免費增值、訂閱、授權、用量計費）。
- 現有方案營收卡住，懷疑是定價結構有問題（例如免費版太好用、付費牆放錯位置）。
- 要評估某個客群或通路值不值得投，需要算 CAC、LTV、毛利。
- 老闆或投資人問「這個產品怎麼賺錢」，需要一頁講清楚。

何時不需要：只是改一個價格數字的 A/B 測試，看 `19-ab-testing.md`；單純估開發成本，看 `06-cost-estimation.md`。

## 動手前先問

1. **付費的是誰？跟使用者是同一人嗎？**
   若沒答：B2B 情境先假設「使用者是員工，付費者是部門主管或 IT」，B2C 假設同一人。
2. **客戶感受到的價值和什麼成正比？**（人數、課程數、觀看時數、儲存量、專案數）
   若沒答：從產品現有用量數據挑一個和留存最相關的指標當候選計價單位，標明待驗證。
3. **目前有哪些實際數字？**（月流失率、平均客單價、獲客成本、主要成本結構）
   若沒答：模板中留空並標「假設值」，先用區間跑一次，看哪個數字最影響結論。
4. **有沒有不能動的限制？**（既有合約、通路分潤、應用商店抽成、集團定價政策）
   若沒答：假設應用商店抽成與通路分潤都存在，並在毛利計算中列出。

## 做法

1. **寫出價值交換的一句話。** 「____（付費者）為了 ____（得到的結果），願意按 ____（計價單位）付錢給我們。」寫不出來，代表商業模式還沒想清楚。
2. **選計價單位。** 判斷標準：客戶覺得公平（用越多、得越多）、容易預測帳單、和我們的成本走向一致。

   | 定價模式 | 適合 | 陷阱 |
   |---|---|---|
   | Freemium | 個人可自行試用、有自然傳播、邊際成本低 | 免費版解決了大部分需求，沒人升級；免費用戶的支援成本被忽略 |
   | 訂閱（按席次） | 價值和使用人數成正比的協作工具 | 客戶共用帳號；大客戶覺得席次費太貴而只買少數席 |
   | 訂閱（按方案分級） | 不同客群需求差異大 | 方案切太細，客戶選不出來；功能分級不符合使用習慣 |
   | 授權（買斷或年授權） | 企業內部部署、SDK、需要可預測採購的客戶 | 後續營收靠續約與維護費，產品更新動力不足 |
   | 用量計費 | 用量差異極大、成本隨用量增加（例如 API 呼叫、簡訊發送則數） | 客戶無法預測帳單而不敢用；營收波動大 |

3. **算單位經濟，一次只看一個客群。**
   - CAC = 該客群一段期間的行銷 + 業務成本 ÷ 新增付費客戶數（成本要含人力，不只廣告費）。
   - LTV = 平均每月毛利 ÷ 月流失率（流失率很低時要設上限年數，例如最多算 3–5 年，避免 LTV 無限大）。
   - 毛利 = 營收 − 直接服務成本（雲端、第三方服務費、商店抽成、客服）。
   - 判斷標準：LTV ÷ CAC 常見的參考線是 3 以上、CAC 回收期在 12–18 個月內（這是業界常用的經驗值，不是硬規則，需依公司現金狀況調整）。
4. **檢查付費牆的位置。** 免費到付費的分界應該落在「用戶已經得到價值、而且需要更多」的時刻，例如超過免費額度、要邀請同事、要用在正式商業場合。判斷標準：能說出「用戶在哪個行為之後最常升級」並有數據支持。
5. **決定商業模式畫布要不要畫。** 新事業、要和不熟產品的人對齊全貌時有用；既有產品調價時通常不需要，直接算單位經濟更有用。
6. **列出最脆弱的假設與驗證方式。** 例如「學員願意為結業證書與作業批改多付費」→ 用 Fake door 或限量方案測付費意願。

## 品質檢查

- [ ] 能用一句話講出誰付錢、為了什麼、按什麼計價。
- [ ] 計價單位和客戶感受到的價值成正比，且說明了理由。
- [ ] 單位經濟按客群分開算，CAC 包含人力成本，毛利扣了商店抽成與第三方費用。
- [ ] LTV 有設年數上限，沒有用極低流失率算出不合理的數字。
- [ ] 付費牆位置有數據或訪談支撐，不是憑感覺。
- [ ] 所有數字都標了來源或「假設值」。
- [ ] 列出最脆弱的假設與驗證方式。

## 常見錯誤

- **CAC 只算廣告費** → 業務和客戶成功的人力才是 B2B 的大頭，只算廣告會讓 CAC 看起來很漂亮 → 把相關人力按工時比例攤進去。
- **全體客戶混在一起算 LTV** → 大企業客戶拉高平均值，掩蓋了小客戶其實在虧錢 → 至少拆成 2–3 個客群分別算。
- **免費版給太多** → 怕沒人用所以把核心功能都放免費，結果升級率極低 → 找出「用戶在何時需要更多」，把付費牆放在那個時刻之後。
- **抄對手的價格** → 對方的成本結構、客群、通路都不同 → 參考對方的計價單位與方案邏輯，但價格從自己的單位經濟與付費意願推。
- **用量計費讓客戶不敢用** → 客戶怕帳單失控，乾脆少用 → 搭配用量上限、預付額度或用量提醒。

## 情境範例

情境：線上課程平台評估從「單堂購買」改為「訂閱＋單堂」並行（以下皆為假設值）。

- 價值交換：想持續進修的上班族為了在一段期間內不限次數學習多門課，願意按「月訂閱」付費；只想學特定技能的人，仍按「單堂」付費。
- 觀察：部分學員一季內購買 3 堂以上單堂課，單堂計價讓他們每次購買都要重新決策，回購間隔拉長（假設值，需用實際購買數據查證）。
- 新結構：訂閱方案可看平台內標示為「訂閱可看」的課程；新上架的熱門講師課程前 3 個月僅開放單堂購買，之後併入訂閱庫。
- 單位經濟（訂閱學員客群）：月營收 NT$499、毛利率 55%（扣除講師分潤、影音串流與商店抽成）、月流失率 6%、LTV 上限 3 年 → 約 NT$4,600；CAC NT$1,200 → LTV/CAC 約 3.8，回收期約 4.4 個月。
- 最脆弱假設：「訂閱不會大幅侵蝕單堂營收」→ 先對 30% 新註冊學員顯示兩種方案，觀察 3 個月內總營收與單堂購買比例的變化。
- 提醒：講師分潤從「按單堂銷售」改為「按訂閱觀看時數」會動到講師合約，與學員的訂閱與退費條款一併交由法務審閱。

## 工具

- `scripts/unit_econ.py --arpu <月營收> --margin <毛利率> --churn <月流失率> --cac <獲客成本>`：算每月毛利、預期壽命、LTV、LTV/CAC 與回收期。多個客群用 CSV 一次算。
- 輸出的敏感度表會標出哪個輸入一變動就讓 LTV/CAC 跨過門檻，那就是最脆弱的假設，先查證它。
- LTV/CAC ≥ 3 這類門檻是經驗值，依產業與成長階段而異，引用時要說明。腳本假設固定流失率、不折現，早期產品的流失率通常還不穩定。
