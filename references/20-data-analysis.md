# 20 數據分析

> 一句話：從一個明確的問題出發，取到對的資料、清乾淨、分析到能支持一個決策，並且不被常見的統計陷阱騙。

## 何時用

- 老闆或同事問「為什麼上個月 XX 掉了？」需要找出原因。
- 要為一個提案提供數據依據（例如要不要投資某平台）。
- 上線後要評估某個改動的影響，但沒有做 A/B 測試。
- 何時不需要：問題已經可以用現成儀表板直接回答；或你需要的其實是「為什麼」，而樣本少到看數據不如直接訪談。

## 動手前先問

1. **這個分析要支持什麼決定？** 若沒答：先假設是「要不要採取某個行動」，並寫出兩個可能結論各會導致什麼行動。
2. **指標的正式定義是什麼？跟誰的定義一致？** 若沒答：沿用公司儀表板的定義，並在報告中寫明。
3. **時間範圍與比較基準？**（上月、去年同期、改版前）若沒答：預設與前一個完整週期比較，並同時看去年同期排除季節性。
4. **期限與精確度要求？** 若沒答：假設要的是「方向正確」的快速答案，先交一版初步結論，再視需要深挖。

## 做法

1. **定義問題。** 把「為什麼營收掉了」改寫成可回答的形式：「____ 指標在 ____ 期間相比 ____ 下降 ____，主要來自哪個分群／哪個環節？」判斷標準：問題中有指標、期間、比較基準。
2. **列出假設，再取數。** 先寫 3–5 個可能原因（季節、改版、追蹤壞掉、某通路、某價格變動），每個寫出「如果是它，資料應該長怎樣」。判斷標準：每個假設都有一個能否定它的資料檢查。
3. **取數。** 記錄資料來源、查詢語法、取數時間。判斷標準：別人照著紀錄能重跑出一樣的數字。
4. **清理。** 依序檢查：
   | 檢查 | 常見問題 |
   |---|---|
   | 重複 | 同一事件記兩次、同一人多帳號 |
   | 缺漏 | 某天或某平台沒資料（多半是埋點或管線壞了） |
   | 異常值 | 內部測試帳號、機器人、極端大客戶 |
   | 定義變更 | 期間內事件改名或計算方式改變 |
   判斷標準：清理規則寫下來，並說明清理前後的數字差多少。
5. **先排除「資料本身的問題」。** 指標突然大變時，第一個要查的是追蹤或資料管線，而不是用戶行為。判斷標準：確認同期間其他相關指標是否同步異常。
6. **分析。** 拆分群（平台、來源、方案、新舊用戶、地區）找變動集中在哪裡。判斷標準：拆到能說出「變動的 ____% 來自 ____」為止。
7. **檢查陷阱。**
   - **辛普森悖論**：整體趨勢與每個分群的趨勢相反，常因為分群組成比例改變。例如每個平台的轉換都上升，但整體下降，因為低轉換平台的流量變多。→ 整體有變化時，一定拆分群看，同時看組成比例。
   - **倖存者偏差**：只看留下來的人。例如「付費用戶最常用的功能」不代表那個功能讓人付費，因為沒看到用過就離開的人。→ 問自己「看不到的那群人是誰」，把他們也納入。
   - **相關不等於因果**：兩個指標一起變，可能都被第三個因素推動（季節、行銷活動）。→ 用時間順序、對照組、或實驗來支持因果；沒有的話寫「相關」。
   - **基數太小**：百分比變化大但人數只有個位數。→ 同時列出絕對數字。
8. **寫結論。** 結論先行，附證據與信心，再寫建議行動。判斷標準：讀者只看第一段就知道要做什麼；每個結論都標明是「已驗證」「推測」或「需實驗確認」。

### 個資實務提醒

- **最小蒐集**：取數時只撈分析需要的欄位，用 user_id 而不是 email 或姓名。
- **去識別化**：分享報告或匯出檔前移除識別欄位；分群過小（例如少於 ____ 人，假設值）時合併或不呈現，避免反推個人。
- **用途限制**：資料只用於蒐集時告知的目的（台灣個資法的特定目的、GDPR 的目的限制）；要拿來做行銷名單需另行確認合法基礎與 CCPA 的選擇退出。
- **保存期限**：分析用的明細檔設定刪除日期，不要長期留在個人電腦或共用雲端。

- **報告格式：** 完整報告（外框見 `modes/report.md`）

- **結論先講：** ____ 的主因最可能是 ____（信心 高／中／低）；已排除 ____；建議 ____。

## 品質檢查

- [ ] 問題有指標、期間、比較基準，且對應到一個決定。
- [ ] 先排除了追蹤或資料管線出錯的可能。
- [ ] 取數與清理步驟可以被別人重現。
- [ ] 有拆分群並檢查組成比例變化。
- [ ] 每個因果說法都有對照或實驗支持，否則寫成相關。
- [ ] 結論在第一段，且標明信心與行動。
- [ ] 報告與匯出檔不含可識別個人的資訊。

## 常見錯誤

- **先撈資料再想問題** → 有資料庫權限就想先看看 → 先寫問題與假設，否則會在資料裡找到任何你想找的東西。
- **指標掉了直接找用戶行為原因** → 預設資料是對的 → 第一步查埋點、管線、定義有沒有變。
- **只看整體平均** → 簡報空間有限 → 至少拆一層分群並看組成比例，辛普森悖論常在這裡出現。
- **把「付費用戶都用 X」當成「X 帶來付費」** → 倖存者偏差加相關當因果 → 比較用過與沒用過 X 的人在使用前的條件是否相同，或用實驗驗證。
- **報告先講方法再講結論** → 想證明自己做得很仔細 → 結論先行，方法放附錄。

## 情境範例

問題：線上課程平台上月新增付費訂閱數比前月下降 ____%（假設值），老闆問原因。
- 假設：季節性、iOS 付費流程改版、開學季促銷結束、追蹤壞掉。
- 先排除資料問題：Android 與網頁的事件數正常，iOS 付費事件在改版當天後減少約一半（假設值），但應用程式商店後台的實際訂閱數只少 ____%（假設值）→ 部分是追蹤漏記。
- 修正追蹤落差後，實際下降約 ____%（假設值）。
- 拆分群：每個平台的轉換率都持平，但低轉換的網頁流量佔比因促銷結束而上升 → 整體下降主要是組成比例改變（辛普森悖論）。
- 結論：付費流程改版本身沒有證據造成下降；需修 iOS 追蹤，並與行銷確認下一波促銷時程。信心中。
- 個資：分析僅用 user_id 與平台欄位，明細檔 ____ 日後刪除。
