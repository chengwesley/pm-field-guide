# 14 資訊架構

> 一句話：讓用戶在不靠搜尋、不靠問人的情況下，猜得到東西放在哪裡、叫什麼名字。

## 何時用

- 功能越加越多，設定頁或選單變成一長串，客服常被問「XX 在哪裡」。
- 要整合兩個產品或模組（例如把訂單管理併進會員中心），需要決定新的分類。
- 新產品或新模組從零開始，要先決定導覽骨架再畫畫面。
- 何時不需要：只是新增一個按鈕到既有、清楚的位置；或問題其實是單一頁面的版面，那是 Wireframe 的事。

## 動手前先問

1. **用戶最常來做的 3–5 件事是什麼？** 若沒答：用使用數據或客服單的高頻問題先排出前 5，標明是推估。
2. **現有架構哪裡最常讓人找不到？** 若沒答：假設是客服「在哪裡」類問題最多的那幾項。
3. **有沒有不能動的部分？**（品牌命名、與其他平台一致的要求、已寫進合約或說明文件的路徑）若沒答：假設頂層選單名稱維持不變，只重整第二層以下。
4. **用戶群是否差很多？**（個人 vs 企業管理員）若沒答：假設要兼顧兩群，主導覽給高頻用戶，管理功能收進獨立區域。

## 做法

1. **盤點內容與功能。** 列出所有頁面、功能、設定，含使用頻率（有數據就用，沒有標假設值）。判斷標準：清單完整到包含那些「很少用但被找不到時會很生氣」的項目，例如帳單與匯出。
2. **做卡片分類。** 選開放式（讓用戶自己分組命名）或封閉式（給定類別讓用戶放）：
   | 情況 | 選 |
   |---|---|
   | 從零開始，不知道用戶怎麼想 | 開放式 |
   | 已有架構草案，要驗證放得對不對 | 封閉式 |
   | 想知道類別名稱怎麼取 | 開放式，看用戶自己取的名字 |
   每次 30–60 張卡（假設值，視內容量），卡片用用戶語言寫，不用內部代號。判斷標準：卡片名稱本身不能洩漏分組答案（不要寫「帳戶設定：密碼」）。
3. **整理分群結果，畫出架構草案。** 看哪些卡片穩定被放在一起，哪些分歧大。判斷標準：分歧大的卡片不要硬塞，標記為「可能需要多入口或改名」。
4. **做樹測試。** 只給文字選單樹（沒有視覺設計），給任務請用戶點到他認為的位置。判斷標準：關鍵任務的成功率與「直接走對」比率事前定門檻（例如 ____%，假設值），未達標的分支要改。
5. **設計導覽。** 決定全域導覽、區域導覽、情境連結、麵包屑、搜尋的分工。判斷標準：最高頻的 3–5 件事從任何頁面最多兩步可達；低頻管理功能可以藏深，但要有一個固定入口。
6. **定標籤命名。** 每個標籤檢查：用戶用不用這個詞？與其他標籤是否互斥？在各平台、各語系是否一致？判斷標準：樹測試中被誤點最多的標籤優先改名，而不是先改位置。
7. **寫架構文件並排遷移。** 舊路徑怎麼導到新位置、說明文件與客服話術要同步更新。判斷標準：上線當天客服拿得到新舊對照表。

## 品質檢查

- [ ] 內容盤點包含低頻但重要的項目（帳單、匯出、刪除帳號）。
- [ ] 卡片與樹測試的用詞是用戶的語言，不是內部代號。
- [ ] 樹測試的門檻是事前定的，不是看完結果才說「還可以」。
- [ ] 前 3–5 個高頻任務都在兩步內可達。
- [ ] 同一層的標籤彼此互斥，用戶不會在兩個選項間猶豫。
- [ ] 有舊新路徑對照，客服與說明文件同步。

## 常見錯誤

- **照組織架構或程式模組分類** → 內部最熟悉這種分法 → 以用戶任務分類，內部歸屬寫在文件裡就好。
- **卡片寫成內部代號或功能名** → PM 自己天天用這些詞 → 改寫成用戶會說的話，找一位非產品部門同事試讀。
- **樹測試做在有視覺的畫面上** → 想一次測完 → 樹測試只測結構，視覺會幫忙或干擾，結果就分不清是哪個造成。
- **「其他」「更多」變成垃圾桶** → 放不進去的東西都丟這 → 每季檢查「更多」裡的項目，高頻的拉出來，沒人用的考慮移除。
- **改了架構但沒排遷移** → 只想著新設計 → 上線前準備舊路徑導向、說明文件更新與客服對照表。

## 情境範例

訂房網站的會員功能散在三個地方：會員中心、首頁右上角選單、App 底部的「我的」。
- 盤點：即將入住、過去訂單、取消中訂單、收藏住宿、優惠券、點數、常用旅客資料、發票等，共 22 項（假設值）。
- 開放式卡片分類 15 人（假設值）：多數人把「即將入住」與「取消中訂單」放一起，命名為「我的行程」。
- 樹測試任務「找到下週入住那筆訂單的取消規定」：成功率 ____%、直接走對 ____%（假設值），誤點最多是「訂單紀錄」。
- 處置：新增頂層「我的行程」，下分「即將入住」「已完成與已取消」；「訂單紀錄」改名為「付款與發票」。
- 遷移：舊連結導到新位置，客服對照表於上線前一週交付，負責人 ____。「常用旅客資料」含個資，換位置時存取權限與遮罩顯示維持不變。
