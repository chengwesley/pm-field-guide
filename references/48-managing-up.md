# 48 向上管理

> 一句話：讓主管在需要知道的時候知道需要知道的事，壞消息早一點、帶著方案、明確說要他做什麼決定。

## 何時用

- 新主管、新專案開始，要對齊期待與回報方式。
- 專案出問題（延期、超支、品質不達標），要跟主管報告。
- 需要主管幫忙：要人、要預算、要他去跟別的部門喬。
- 覺得主管常在你沒預期的時候追問進度，或回報後沒有回應。

何時不需要：正式提案爭取新資源（看 `47-proposal-persuasion.md`）；跟主管有明顯衝突或績效爭議（找 HR 或更高主管討論）。

## 動手前先問

1. **主管怎麼衡量你做得好不好？** 若沒答：直接問他「三個月後，你覺得我做到什麼就算做得好？」不要自己猜。
2. **主管喜歡怎麼收資訊？** 書面或口頭、細節或結論、定期或有事才講。若沒答：觀察他回哪種訊息比較快，先假設「結論先行的短書面＋定期一對一」。
3. **主管的主管在追什麼？** 若沒答：從公司或部門目標推，並在一對一時確認。
4. **這件事是要主管知道、要他給資源，還是要他做決定？** 若沒答：先自己分類，分不出來代表還沒想清楚。

## 做法

1. **對齊期待。** 新關係或新專案開始時，花 30 分鐘談：成功的標準、哪些事你可以自己決定、哪些要先問、回報頻率與形式。判斷標準：談完後你能寫出「這些我自己決定，這些要先報」的清單，並請主管確認。
2. **建立固定回報節奏。** 例如每週一則書面週報＋雙週一對一。判斷標準：主管很少需要主動追問你的進度。如果常被追問，表示節奏或內容不符合他的需要，要調整。
3. **壞消息報得早。** 判斷規則：你自己有 50% 以上的把握某個承諾會跳票，就該報了，不要等到確定。越早報，主管能動用的選項越多。
4. **壞消息帶方案。** 結構：發生什麼事 → 影響（時程、成本、客戶）→ 原因 → 我考慮過的選項 → 我建議哪個 → 需要你決定什麼、何時前。判斷標準：主管聽完可以直接說「好，照 B」或「我需要再想想到 ____」，而不是反問一堆基本問題。
5. **分清要資源還是要決策。**

   | 類型 | 你要說的 | 例子 |
   |---|---|---|
   | 告知 | 「讓你知道，不需要你做什麼」 | 進度、小風險已處理 |
   | 要決策 | 「請你在 A、B 中選一個，____ 前」 | 延期還是縮範圍 |
   | 要資源 | 「我需要 ____，用來 ____，沒有的話 ____」 | 多一個 RD 兩週 |
   | 要幫忙喬 | 「需要你跟 ____ 談 ____，因為 ____」 | 跨部門優先級衝突 |

   在訊息第一行就標明類型。
6. **依主管風格調整。** 不是迎合，而是讓資訊有效到達。
   - 要結論的：第一句就給建議與要的決定，細節放附件。
   - 要細節的：附上數據與推導過程，預留時間讓他問。
   - 想參與的：早期就邀他看草稿，而不是給完成品。
   - 放手型的：主動約一對一，不要因為他沒問就不報，出問題時才會措手不及。
   判斷標準：同樣的資訊，主管第一次看就抓到重點，不用來回補問。

## 產出模板

- **報告格式：** 短版（外框見 `modes/report.md`）
- **標題：** 週報：____（給主管）或 壞消息報告：____
- **結論先講：** 週報：狀態 綠／黃／紅；最需要你知道的是 ____。壞消息：先講結論 ____；我建議 ____，需要你決定 ____。

下面是本文的模板。

```markdown
### 週報（給主管）
- 本週結論：____（一句話：正常／有風險／需要你決定）
- 需要你：____（決定／資源／幫忙喬，期限 ____）；沒有則寫「無」
- 進度：____（對照里程碑）
- 風險與處理：____
- 下週重點：____

### 壞消息報告
- 類型：要決策
- 發生什麼：____
- 影響：時程 ____／成本 ____／客戶 ____
- 原因：____
- 選項
  - A：____（代價 ____）
  - B：____（代價 ____）
- 我的建議：____，因為 ____
- 請你在 ____ 前決定：____
```

### 話術

- 對齊期待：「為了確保我做的方向是你要的，想跟你確認三件事：三個月後怎樣算做得好、哪些事我可以自己決定、你希望我多久、用什麼方式更新你。」
- 報壞消息：「先講結論：____ 會晚兩週。原因是 ____。我有兩個選項，我建議 B，需要你在週五前決定。」——第一句就講最壞的部分，主管不用聽完鋪陳才知道嚴重性；後面立刻接方案與決策請求。
- 要資源：「我需要多一位 RD 兩週，用來 ____。沒有的話，____ 會延到 ____，影響 ____ 客戶。」——資源跟後果綁在一起，主管才能權衡。
- 覺得被過度追問時：「我發現你最近常需要問我進度，是不是我的更新方式不夠用？你希望我多報什麼？」

## 品質檢查

- [ ] 有一份經主管確認的「自己決定／要先報」清單
- [ ] 週報第一行就是結論與需要主管做的事
- [ ] 壞消息在有把握會跳票時就報，不是確定才報
- [ ] 壞消息報告至少有兩個選項與一個建議
- [ ] 每個需要主管做的事都寫了期限
- [ ] 訊息標明是告知、要決策、要資源還是要幫忙喬

## 常見錯誤

- **壞消息等確定了才報** → 主管失去處理空間，也會開始懷疑你其他回報 → 50% 把握就先報，附上你還在確認的部分。
- **只帶問題不帶方案** → 主管要自己想解法，你的角色變成傳話 → 至少帶兩個選項與一個建議。
- **週報寫成工作日誌** → 主管讀不出重點，會漏掉你真正需要他處理的事 → 第一行寫結論與需求，細節往後放。
- **把主管的沉默當同意** → 他可能根本沒看到，出事時你們記得的不一樣 → 需要決策的事要拿到明確回覆，必要時當面確認。
- **向上管理變成報喜不報憂** → 短期好看，長期信任破產 → 固定回報裡就要有風險欄，平常有在報，出事時才不突兀。

## 情境範例

電商 App 的 iOS 改版預計月底上線，PM 在第三週發現第三方元件授權問題，有 60% 機率延期兩週（假設值）。

- 週報第一行：「有風險，需要你週四前決定。」
- 發生什麼：使用中的 ____ 元件授權條款變更，需要換掉或重新談授權。
- 影響：上線延兩週；原本配合的行銷檔期要調整。
- 選項：A 延兩週換掉元件（成本 ____ 人天）；B 如期上線但暫時拿掉相關功能，下一版補回。
- 建議：B，因為行銷檔期已對外預告（需確認），而該功能使用比例約 ____%（需查證）。
- 請主管：週四前決定；如果選 A，需要主管跟行銷主管談檔期。
- 授權條款的解讀請法務確認後再做最終決定。
