# 13 漏斗分析

> 一句話：在一連串步驟中找出流失最多、而且最值得處理的那一步，並分清楚人是「不想要」還是「做不到」。

## 何時用

- 註冊、付費、首次開立發票這類多步驟流程的整體轉換偏低，要知道掉在哪。
- 改版後轉換率變了，要定位是哪一步造成。
- 要排優化優先順序，需要一個「修哪一步效益最大」的依據。
- 何時不需要：流程只有一兩步；或者每天進漏斗的人數太少，週與週之間的波動比任何改動都大，這時先做訪談或易用性測試。

## 動手前先問

1. **漏斗的起點與終點是什麼？** 若沒答：起點用「明確表達意圖」的事件（例如點了「開立發票」），終點用「得到價值」的事件（發票開立成功），而不是頁面瀏覽。
2. **時間窗多長？** 若沒答：先參考正常用戶完成流程的時間分布，取約 90% 的人能完成的時間（假設值，需查實際分布），而不是隨便定 30 天。
3. **步驟要嚴格依序嗎？** 若沒答：先假設可以跳步但不能倒序，並在報告中註明。
4. **要比較哪些分群？** 若沒答：至少拆平台與新舊用戶。

## 做法

1. **定義步驟。** 每一步對應一個可驗證的事件，3–7 步為宜。判斷標準：每一步都是用戶的「動作」，不是系統的頁面載入；兩步之間沒有用戶不經過就能到下一步的捷徑。
2. **定時間窗與計算單位。** 決定以「人」或「工作階段」計算、時間窗多長、重複進入怎麼算。判斷標準：寫成一句話後，兩位分析師拿同一份資料算出相同數字。
3. **算每一步的轉換與絕對流失人數。** 同時列「步驟轉換率」與「流失人數」。判斷標準：優先看流失人數 × 這群人的價值，而不是轉換率最低的那步。轉換率低但人數少的步驟，修好也影響有限。
4. **拆分群。** 依平台、來源、新舊用戶、方案拆開。判斷標準：如果某一群的漏損特別嚴重，問題通常在那一群特有的條件（例如某平台的日期或下拉選單元件）。
5. **區分流失原因。** 用下表分類，每類對應不同手段：
   | 類型 | 訊號 | 對應手段 |
   |---|---|---|
   | 做不到（技術） | 錯誤事件、特定平台集中、載入時間長 | 修 bug、效能 |
   | 不會做（易用性） | 停留很久、反覆返回、客服問題集中 | 易用性測試、改介面 |
   | 不想做（價值／時機） | 快速離開、之後又回來完成 | 調整時機或訊息，不一定要改流程 |
   | 不該在漏斗裡 | 來源不精準、只是瀏覽 | 修正起點定義或導流 |
6. **提出假設並驗證。** 每個要改的地方寫成「改 ____，預期 ____ 步驟轉換從 ____ 到 ____」。判斷標準：有量測方法（A/B 或前後比較加控制條件），有事前寫定的門檻。
7. **改完回頭看整條漏斗。** 判斷標準：某一步轉換變好，但下一步變差，可能只是把流失往後推。

### 個資實務提醒

- 漏斗分析用內部 user_id，不在報表中放 email、姓名或交易明細。
- 若要把流失名單交給業務或行銷聯絡，需確認用戶當初同意的用途是否涵蓋行銷（台灣個資法的特定目的、GDPR 的合法基礎、CCPA 的選擇退出）。
- 分群人數過少時不要對外呈現細項，避免反推個人。名單類匯出設定保存期限並在用完後刪除。

## 品質檢查

- [ ] 起點是「有意圖」的事件，不是首頁瀏覽。
- [ ] 時間窗與計算單位寫清楚，換人算也會得到同樣結果。
- [ ] 同時列出轉換率與流失人數，優先順序依影響量而不是比率。
- [ ] 至少拆了一個分群，並說明有沒有差異。
- [ ] 每個漏損點都歸類了流失原因，且附證據。
- [ ] 改善提案都有事前寫定的成功門檻。

## 常見錯誤

- **起點定在首頁瀏覽** → 最大的流失永遠是第一步，結論變成「首頁要改」 → 起點改成用戶表達意圖的動作，首頁導流另外分析。
- **時間窗隨便定** → 預設工具給什麼就用什麼 → 先看完成時間分布再定；B2B 審批這種會等別人的流程，時間窗通常要拉長。
- **只盯轉換率最低的那步** → 比率最好比 → 乘上流失人數與這群人的價值再排序。
- **把所有流失都當介面問題** → PM 手上最直接的工具是改介面 → 先分類流失原因；「不想做」的人改按鈕也沒用。
- **改了一步就宣布成功** → 只看了那一步 → 改完看整條漏斗終點有沒有變好。

## 情境範例

記帳 SaaS 新用戶「首次開立發票」漏斗，時間窗 7 天（假設值），以人計算。
- 1 點擊「開立發票」 1,000 人 → 2 填寫公司基本資料 720 人（72%）→ 3 新增買方與品項 430 人（60%）→ 4 確認稅額 390 人（91%）→ 5 送出開立 370 人（95%）。以上皆為假設值。
- 最大流失人數在步驟 2→3（290 人）。
- 分群：行動版在此步轉換比桌機低 ____ 個百分點（假設值）。
- 原因判讀：停留時間長、反覆切換稅別欄位 → 歸類「不會做」，信心中。
- 下一步：先做 5 人易用性測試確認，再提出「從常用品項自動帶入單價與稅別」的 A/B 假設，門檻事前定為步驟轉換 +____ 個百分點。
- 提醒：發票欄位與稅額計算的說明涉及稅務法規，對外文案需交由法務或會計審閱；買方統編、聯絡人屬客戶資料，報表只用內部 id。
