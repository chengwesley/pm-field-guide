# 05 Roadmap 規劃

> 一句話：把策略翻成「接下來依序要解決哪些問題」，同時讓不同讀者對承諾程度有正確預期。

## 何時用

- 季度或年度規劃，要決定團隊接下來做什麼。
- 業務、客服或老闆要一份「什麼時候會有 XX 功能」的答案。
- 對外要公布產品方向（給客戶、合作夥伴、官網）。
- 現有 roadmap 是一長串功能清單，大家看不出重點，想重整。

何時不需要：兩週內的開發排程屬於 sprint 計畫與時程管理（27）；還沒有策略時，先做 `04-product-strategy.md`，否則 roadmap 只是把需求按時間排。

## 動手前先問

1. **這份 roadmap 給誰看？**（團隊、主管、業務、客戶）
   若沒答：預設做兩個版本——對內詳細版與對外簡化版。
2. **策略重點與本期目標是什麼？**
   若沒答：從最近一份策略文件或 OKR 摘出來；找不到就先寫假設的 2–3 個目標，請使用者確認。
3. **有沒有已經對外承諾的日期？**（大客戶合約、法規期限、行銷檔期）
   若沒答：假設沒有，但在產出中加一欄「外部承諾」請使用者補。
4. **團隊產能大約多少？**
   若沒答：以「人數 × 可用週數 × 0.6」估算可投入的產能（扣掉維運、支援與會議，係數為經驗假設，請依團隊實況調整）。

## 做法

1. **選格式。**

   | 格式 | 適合 | 不適合 |
   |---|---|---|
   | Now / Next / Later | 不確定性高、需要保留調整空間、對外溝通 | 有硬性外部日期的項目 |
   | 時間軸（季度或月） | 有法規期限、合約交付、跨團隊依賴需要對齊 | 探索期產品；會被誤讀為承諾 |

   常見做法是主體用 Now / Next / Later，有硬期限的項目另外標出日期。
2. **以成果為單位，而不是功能。** 每個 roadmap 項目寫成「要解決的問題 + 預期成果」，功能是可能的解法。例如寫「讓專案負責人一眼看出哪些任務卡住（逾期任務的平均處理天數 ____ → ____）」，而不是「看板 UI 改版」。判斷標準：項目被砍掉時，大家能說出失去了什麼成果。
3. **依確定程度分欄。**
   - Now（本季）：問題與解法都確定，已估過工、已排人。
   - Next（下季）：問題確定，解法還在探索。
   - Later：方向性的問題，可能改變或取消。
   判斷標準：Later 欄不放具體功能名稱與日期。
4. **核對產能。** Now 欄的總估工不超過可用產能的 70–80%（保留處理突發與技術債，比例依團隊歷史調整）。超過就砍或移到 Next，而不是壓縮估工。
5. **區分承諾與預測，並寫在文件上。** 承諾：有外部依賴或合約、團隊同意、會盡全力守住。預測：目前最好的估計，可能變動。每個有日期的項目都標清楚是哪一種。
6. **做對內與對外兩個版本。**
   - 對內：成果、指標、負責人、估工、依賴、風險。
   - 對外：只講要解決的客戶問題與大致方向，不寫具體日期（除非是承諾），不寫內部代號與未定功能。
7. **定更新節奏與變更規則。** 每月或每季更新一次；項目移動時寫一行原因，並通知受影響的人。

## 產出模板

```markdown
### 對內 Roadmap：____（產品）　更新日期 ____　下次更新 ____
策略重點：1) ____　2) ____

### Now（本季，已承諾或高信心）
| 問題／成果 | 指標（現況 → 目標） | 對應策略 | 負責人 | 估工 | 承諾／預測 | 依賴與風險 |
|---|---|---|---|---|---|---|
| ____ | ____ → ____ | ____ | ____ | ____ 人週 | ____ | ____ |

產能核對：可用 ____ 人週 × 0.75 = ____；Now 合計 ____ 人週

### Next（下季，問題確定、解法探索中）
| 問題／成果 | 對應策略 | 待驗證的事 |
|---|---|---|

### Later（方向）
- ____

### 本期明確不做
- ____（原因 ____）

### 變更紀錄
| 日期 | 項目 | 變更 | 原因 | 已通知 |
|---|---|---|---|---|
```

```markdown
### 對外 Roadmap：____（產品）
**我們正在解決：** ____（客戶問題，用客戶的話）
**接下來會探索：** ____
**長期方向：** ____
備註：以上為目前規劃方向，內容與時程可能依回饋調整。
```

## 品質檢查

- [ ] 每個項目寫的是問題與成果，不只是功能名稱。
- [ ] Now 欄的估工總和有和產能核對過，並保留緩衝。
- [ ] 每個有日期的項目都標了「承諾」或「預測」。
- [ ] Later 欄沒有具體日期與功能規格。
- [ ] 對外版本沒有內部代號、未定功能或非承諾日期。
- [ ] 有「本期不做」與變更紀錄。
- [ ] 每個項目都能對應到一個策略重點。

## 常見錯誤

- **roadmap 就是功能清單加日期** → 日期被當成承諾，延誤時信任受損，功能做完也不知道有沒有用 → 改寫成問題與成果，日期只放在真的有承諾的項目。
- **對外版本直接用對內版本** → 客戶看到未定功能的日期，業務拿去成交，最後做不出來 → 永遠做兩個版本，對外版請行銷與業務主管一起看過。
- **把產能排滿** → 一有客訴或資安修補就全線延誤 → 預留 20–30% 緩衝，並把技術債項目明確列進 Now。
- **每個利害關係人的需求都塞進去** → roadmap 失去方向 → 每個項目先過「對應哪個策略重點」，對應不到的放到「本期不做」並回覆原因。
- **更新時悄悄移動項目** → 業務發現時才知道延了 → 寫變更紀錄，主動通知受影響的人。

## 情境範例

情境：團隊專案管理 SaaS 下一季的對內 roadmap 片段（數字皆為假設值）。

- 策略重點：讓跨部門團隊在同一個工作區追進度，而不只是單一小組的待辦清單。
- Now：「跨團隊任務卡住沒人發現」→ 逾期任務的平均處理天數 ____ → ____；負責人 ____；估工 8 人週；預測。
- Now：「企業客戶需要操作稽核紀錄」→ 有一家合約客戶的期限 ____；承諾。
- Next：「多人同時改同一張任務卡互相覆蓋」→ 問題已確認，解法在比較即時合併與編輯鎖定兩種方式。
- Later：與外部行事曆、通訊工具的雙向同步。
- 產能核對：可用 20 人週 × 0.75 = 15；Now 合計 14 人週。
- 對外版本只寫：「我們正在讓跨部門團隊更容易看到彼此的進度。」
- 提醒：稽核紀錄會保存成員姓名、IP 與操作時間，涉及個資法規（台灣個資法、GDPR、CCPA）與合約條款，對外前需經法務確認。
