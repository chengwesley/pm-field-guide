# 07 KPI 設定

> 一句話：選出能真實反映用戶得到價值的指標，並在動手前寫定「多少算成功」。

## 何時用

- 新產品、新功能或新季度開始，要定目標。
- 團隊有一堆儀表板但不知道該看哪個，或每次檢討都在挑對自己有利的數字。
- 要寫 OKR，不知道 KR 怎麼寫才不是任務清單。
- 上線後要判斷功能成不成功，發現事前沒定標準。

何時不需要：還在探索問題、連目標客群都不確定時，先做用戶研究；硬訂 KPI 會讓團隊過早優化錯的東西。

## 動手前先問

1. **這個產品或功能為用戶創造的核心價值是什麼？**
   若沒答：從「用戶付費或留下來的主要理由」推一個，標為「假設，請確認」。
2. **目前能追蹤到哪些數據？有沒有歷史基準？**
   若沒答：先列出想要的指標，標註「需確認埋點」，基準值留空。
3. **這組 KPI 要對齊哪個上層目標？**（公司 OKR、策略重點）
   若沒答：從最近的策略文件找；找不到就請使用者提供，先以「提升付費轉換」作為暫定上層目標。

## 做法

1. **選北極星指標。** 標準：
   - 反映用戶得到的價值，而不只是我們得到的營收。
   - 領先於營收（它上升，營收之後會跟著上升）。
   - 團隊的工作能影響它。
   例如外送平台用「每週準時送達的訂單數」比「註冊數」好，因為準時送達才代表價值被交付。
2. **拆成 3–5 個輸入指標。** 問「北極星由哪些因素組成」，常見拆法是：觸及 × 啟用 × 使用頻率 × 留存。判斷標準：每個輸入指標都有一個團隊可以直接負責、並在一季內推得動。
3. **設護欄指標。** 推動主指標時可能被犧牲的東西：錯誤率、客訴數、退款率、載入時間、取消訂閱率。每個主要 KR 至少配一個護欄，寫明「不可低於／高於 ____」。
4. **辨識虛榮指標。** 自問三題：它會不會只升不降（累積註冊數）？它變了，我們會不會做不同的決定？它能不能被灌水而不代表價值（頁面瀏覽、下載數）？任一題答「是」，就不要當主要 KPI。
5. **寫 OKR。** Objective 是方向與意義，用文字寫；Key Result 是可量化的結果，不是要做的事。
   - 差：「KR：上線店家端接單頁改版。」（這是任務）
   - 好：「KR：店家 3 分鐘內接單率從 ____% 提升到 ____%。」
   每個 O 配 2–4 個 KR，至少一個是成果指標，不全是產出指標。
6. **事前寫定成功門檻。** 在開工前寫下：基準值、目標值、量測期間、量測方法、低於多少算失敗、失敗後要做什麼。判斷標準：一個不在團隊裡的人看了，能在期末自己判定成功或失敗。
7. **確認資料來源與埋點。** 每個指標寫出定義（分子、分母、時間窗、排除條件）與資料來源。涉及用戶行為追蹤時，確認隱私權政策有涵蓋、蒐集範圍最小化、並依台灣個資法、GDPR、CCPA 處理同意與去識別化。

## 產出模板

- **報告格式：** 完整報告（外框見 `modes/report.md`）
- **標題：** KPI 設計：____（產品或功能）
- **結論先講：** 北極星指標是 ____；本期門檻是 ____ 從 ____ 到 ____，護欄是 ____。

## 品質檢查

- [ ] 北極星指標反映用戶價值，且說明了為什麼選它。
- [ ] 每個指標都有明確定義（分子、分母、時間窗、排除條件）。
- [ ] 每個 KR 是可量化的結果，不是要做的任務。
- [ ] 每個主要目標都配了護欄指標。
- [ ] 成功與失敗門檻在開工前寫定，並標了日期。
- [ ] 沒有用累積型或可灌水的指標當主要 KPI。
- [ ] 每個輸入指標都有負責人與資料來源。

## 常見錯誤

- **KR 寫成任務** → 「完成 3 個功能上線」做完了也不知道有沒有用 → 改成功能要帶來的結果，任務放到 roadmap。
- **事後挑指標** → 上線後看哪個數字漂亮就報哪個，團隊學不到東西 → 開工前寫定成功門檻，期末照表判定。
- **沒有護欄** → 為了拉高轉換率把取消訂閱流程藏起來，客訴與退款跟著上升 → 每個主指標配一個可能被犧牲的指標。
- **指標太多** → 15 個 KPI 等於沒有重點 → 北極星 1 個、輸入指標 3–5 個，其他放監控儀表板。
- **定義不清** → 「活躍用戶」每個人算法不同，會議花一半時間在爭數字 → 寫下定義並放在共用文件，任何改動都記錄日期。

## 情境範例

情境：外送平台「店家端」下一季的 KPI（數字皆為假設值）。

- 北極星：每週店家成功出餐並交給外送員的訂單數（店家接單、在承諾時間內出餐並完成交接，排除測試店家與取消單）。
- 輸入指標：每週有接單的活躍店家數（負責人 ____）；店家 3 分鐘內接單率 62% → 70%（負責人 ____）；接單到出餐完成的中位數時間 ____ → ____。
- 護欄：店家端拒單率不高於 ____%；店家客服相關工單不增加超過 ____%。
- OKR：O「讓店家在尖峰時段也接得住單」；KR1 店家 3 分鐘內接單率 62% → 70%；KR2 活躍店家數成長 ____%。
- 成功門檻（開工前寫定）：上線後 4 週接單率 ≥ 68% 算成功；< 64% 則回頭做可用性測試。
- 虛榮指標提醒：「店家端 App 下載數」不列入，因為無法反映店家是否真的在接單出餐。
- 提醒：店家負責人資料與訂單中的消費者姓名、地址屬個人資料，需確認隱私權政策涵蓋、只蒐集必要欄位；涉及店家抽成與合約條款的指標說明，對外前需交由法務審閱。
