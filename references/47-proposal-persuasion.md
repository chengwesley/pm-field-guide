# 47 提案說服

> 一句話：先弄清楚決策者在意什麼，再用一頁講清楚「問題、方案、代價、要你決定什麼」，讓對方能當場做決定。

## 何時用

- 要爭取資源、預算、人力做一個新產品或新功能。
- 要說服主管或高層改變既有方向（例如停掉某個功能、換優先級）。
- 跨部門提案，需要對方部門投入。
- 上次提案被拒，準備再提。

何時不需要：例行進度報告（看 `48-managing-up.md`）；簡報的敘事結構與講稿細節（看 `40-presentation-making.md`）。

## 動手前先問

1. **誰是最後拍板的人？他今年被什麼指標考核？** 若沒答：假設是你的上兩層主管，先從公司或部門年度目標推他在意的事，並在會前找他身邊的人確認。
2. **你要對方決定什麼？** 給錢、給人、給時間、還是同意方向？若沒答：先寫一句「我請你同意 ____」，寫不出來代表還沒準備好提案。
3. **對方現在對這件事的立場？** 支持、中立、反對、不知道。若沒答：假設中立偏保留，準備好反對意見的回應。
4. **不做的代價是什麼？** 若沒答：至少寫出「維持現狀的成本」，即使是估計值也要標假設。

## 做法

1. **摸清決策者在意什麼。** 從三個來源找：他公開講過的目標、他最近否決或通過了什麼、他身邊的人怎麼描述他的顧慮。判斷標準：你能用一句話寫出「他最怕 ____，最想要 ____」。
2. **會前個別溝通。** 重要提案不要在會議上第一次曝光。先找關鍵利害關係人各聊 15 分鐘，聽反對意見並調整。判斷標準：開會時沒有任何關鍵人物是第一次聽到。
3. **寫一頁提案。** 結構見模板。判斷標準：決策者只讀第一段就知道你要他決定什麼。
4. **預演反對意見。** 列出最可能的 3–5 個反對理由，每個準備一句回應與一個證據。常見的反對類型：太貴、太慢、不是現在、風險太高、跟別的事衝突、證據不足。
5. **數據與故事搭配。** 用一個具體使用者或客戶的故事讓問題變真實，用數據說明這不是個案。判斷標準：故事不超過三句；數據每個都有來源或標假設值。只有故事會被認為是個案，只有數據會讓人記不住。
6. **給選項，不給單一答案。** 至少準備：完整方案、精簡方案、不做。讓決策者在選項中選，而不是只能對你說 Yes 或 No。
7. **被拒後。** 先問清楚是哪一種拒絕：方向不對、時機不對、證據不夠、資源不夠。依類型決定：放下、等時機、補證據、縮範圍。判斷標準：離開會議前知道「什麼條件下可以再提」。

## 產出模板

- **報告格式：** 完整報告（外框見 `modes/report.md`）
- **標題：** 一頁提案：____（主題）
- **結論先講：** 請核准 ____；預期 ____，不做的代價是 ____。

下面是本文的模板。

```markdown
### 一頁提案
**請你決定：** 同意 ____（投入 ____ 人／____ 週／預算 ____）

**問題：** ____（一句故事＋一個數據，數據標來源或假設值）

**不處理的代價：** ____（營收／成本／流失／風險）

**方案選項**
| | 完整方案 | 精簡方案 | 不做 |
|---|---|---|---|
| 內容 | ____ | ____ | 維持現狀 |
| 投入 | ____ | ____ | 0 |
| 預期效果 | ____ | ____ | ____ |
| 主要風險 | ____ | ____ | ____ |

**我的建議：** ____，因為 ____

**成功怎麼判斷：** ____ 指標在 ____ 前達到 ____；未達到時 ____（停止／調整）

**需要的支援：** ____
```

### 話術

- 開場：「今天想請你決定一件事：要不要投入 ____ 做 ____。我先用兩分鐘講為什麼，再請你選方案。」——一開始就講清楚要什麼，決策者不用猜。
- 回應「太貴」：「完整方案確實要 ____。精簡方案 ____ 就能先驗證最關鍵的假設，如果 ____ 週後指標沒達到 ____，我們就停。」——把大賭注拆成小實驗，並主動提出停損點。
- 回應「不是現在」：「理解。可以請你告訴我，什麼條件出現時你會覺得是時候？我會追那個條件，到了再來找你。」——把模糊的拒絕變成可追蹤的條件。
- 被拒後：「謝謝你直接告訴我。我想確認一下，主要是 ____ 的顧慮嗎？如果我補上 ____，值得再談一次嗎？」

## 品質檢查

- [ ] 第一段就寫明要對方決定什麼
- [ ] 有「不做」選項與不處理的代價
- [ ] 每個數據都有來源或標「假設值」
- [ ] 有事前寫定的成功門檻與停損條件
- [ ] 反對意見預演至少 3 條，每條有回應與證據
- [ ] 關鍵利害關係人會前都已個別溝通過
- [ ] 涉及定價、合作夥伴、對外宣布的內容已標示需主管審閱

## 常見錯誤

- **從自己覺得重要的角度講** → 決策者在意的是他的指標，不是你的功能 → 用他在意的指標重寫問題與效果。
- **只給一個方案** → 決策者只能說 Yes 或 No，No 的機率更高 → 至少給完整、精簡、不做三個選項。
- **在會議上第一次曝光** → 被當場問倒，或有人覺得被忽略而反對 → 會前個別溝通，把反對意見提前消化。
- **用一大堆數據堆說服力** → 決策者記不住，也會懷疑數據挑過 → 一個故事＋一到兩個關鍵數據，其他放附錄。
- **被拒後直接放棄或隔週再提一樣的** → 沒處理拒絕的原因，再提也一樣 → 問清楚拒絕類型與再提的條件。

## 情境範例

PM 想提案讓健身訂閱 App 投入 ____ 人／____ 週（假設值）做「訂閱到期前的方案提醒與挽留流程」。

- 決策者在意：BU 主管今年考核訂閱續訂率（需確認）。
- 問題：一位年繳會員在客服說「沒注意到已經續訂扣款，想退費」；同類退費工單上季 ____ 張（假設值，需查證）。
- 不處理的代價：退費與爭議處理的客服工時 ____ 小時、續訂率可能受影響（需查證）。
- 選項：完整方案（到期前提醒＋方案比較＋挽留優惠，____ 週）／精簡方案（只做到期前 App 內與 email 提醒，____ 週）／不做。
- 建議：精簡方案，____ 週後看退費工單是否下降 ____%；未下降則停止並重新檢視。
- 反對預演：「提醒會讓更多人取消」→ 回應：先在小比例用戶上做 A/B 測試，看續訂率與退費率的淨效果。
- 挽留優惠涉及定價，需定價負責人確認。

對外使用前需經相關主管審閱。
