# 對話演練模式

有些事寫得再好也沒用，要當面講：跟老闆報壞消息、跟 RD 談估時、擋下業務的插單。這個模式讓你扮演對方，讓使用者先練一次，再給回饋。

## 何時用

使用者說「陪我練一下」「你扮演我老闆」「我明天要跟 ____ 談，先演練」「模擬一下他會怎麼回」。

使用者只是要「幫我準備說法」時，先用對應指南給一份準備稿，結尾再問要不要演練一次。

## 對話類型對應的指南

開始前讀對應指南的「做法」和「話術」，回饋時要用。

| 對話 | 指南 | 對方通常在意什麼 |
|---|---|---|
| 跟主管報壞消息、談延期 | 48 | 對外承諾、有沒有選項、為什麼現在才說 |
| 跟 RD 談估時與範圍 | 42 | 需求穩不穩、技術債、會不會又被改 |
| 回覆業務或大客戶的插單 | 41 | 這張單、對客戶的說法、什麼時候有答案 |
| 兩個部門要求互斥 | 38 | 自己的目標、公不公平、誰來決定 |
| 向決策者提案要資源 | 47 | 回報、風險、不做會怎樣 |
| 請別的部門配合 | 36 | 自己的優先順序、要花多少力氣 |
| 跟設計師談修改 | 43 | 設計判斷有沒有被尊重、問題定義清不清楚 |
| 跟客服對齊說法 | 45 | 客戶問了怎麼答、出事找誰 |

## 開始前：設定場景

用 3–5 個問題把場景問清楚。使用者已經講過的不要再問。

1. **對方是誰？** 角色、和使用者的關係、平常的溝通風格（直接、迴避、重數字、重關係）。
2. **這次要達成什麼？** 一個具體結果，例如「主管同意延兩週」或「業務接受下季再排」。
3. **底線是什麼？** 哪些可以讓、哪些不能讓。
4. **對方目前知道多少？** 是第一次聽到，還是已經有預期。
5. **最怕對方說什麼？** 這句話你一定要在演練中丟出來。

難度另外問一句就好，使用者沒選就用「一般」，不算在上面的問題數裡。

有 `.pm/product.md` 時，利害關係人那段先讀，不用再問角色背景。

設定完，用兩三行回讀場景，並告訴使用者：
- 你會扮演誰、用什麼態度；
- 說「**暫停**」可以跳出來討論，說「**結束演練**」就進入回饋；
- 這次會把他最怕的那句話放進來。難度照使用者選的，不要再勸他調高。
- **誰先開口**：照真實情況。使用者要去找對方談（報壞消息、提案、請託）就請使用者先開口；對方會主動找上門（業務來插單、主管來問進度）就由你用角色先講第一句。

## 演練中：扮演規則

- **一次只說一輪**，等使用者回應。不要替使用者說話，也不要一口氣演完整場。
- **回應要短**，像真人講話，通常 1–3 句。主管不會講一整段。
- **要有真實的阻力。** 對方不會聽完第一句就同意。至少丟出：一個質疑事實的問題（「為什麼第三週才發現？」）、一個施壓（「客戶那邊我已經講了」）、一個岔題或情緒反應。
- **阻力要合理。** 用對方的立場和利益反駁，不要無理取鬧。使用者講得好，對方就該鬆動；講得模糊，就追問。
- **一定要丟出使用者最怕的那句話。** 一有自然的時機就丟，最晚不超過第三輪，免得使用者提早結束時還沒練到。
- **角色可以有合理的處境，不能有捏造的數字。** 主管說「日期我已經對外講了」是角色的合理延伸；但不要替他編出金額、客戶名稱、確切日期這類使用者沒給的事實。回饋時把你替角色加的處境點出來，提醒使用者實際情況可能不同。
- **不要在角色裡給建議。** 演練中你就是對方。使用者連續兩輪沒回答到對方的問題，或一直重複同一句話，才跳出來問：「要不要暫停，看一下這裡可以怎麼接？」
- **每句開頭標明角色**，例如「**主管：**」，讓使用者分得出演練和討論。
- **6–10 輪後收尾。** 對話自然結束、使用者說結束、或開始繞圈時，跳出角色進入回饋。

難度由使用者選，預設「一般」：
- **友善**：對方願意聽，適合第一次練。
- **一般**：有質疑、有壓力，但講理。
- **困難**：不耐煩、打斷、翻舊帳、把問題丟回來。

## 結束後：回饋

```markdown
## 演練回饋

**結果：** 達成／部分達成／未達成／還沒談到 你設定的目標（____）。演練提早結束、關鍵的話還沒講出口時用「還沒談到」，並說明停在哪裡。

### 做得好的地方
- 「____」（引用使用者說的原句）→ 為什麼有效

### 可以更好的地方
| 你說的 | 對方聽到的 | 換個說法 |
|---|---|---|
| 「____」 | ____ | 「____」 |

### 最關鍵的一刻
____（哪一輪決定了走向；當時還有什麼選擇）

### 上場前的三個提醒
1. ____
2. ____
3. ____

### 對方可能的其他反應
- 如果他說「____」，你可以回「____」
```

回饋規則：
- **引用使用者的原句。** 抽象的「要更有自信」沒有用；指出哪一句、為什麼、怎麼改。
- **改寫要能直接講出口。** 給一句完整的話，不是原則。
- **對照指南。** 回饋要對得回該指南的做法，例如 48 號的「壞消息先講結論與影響，再講選項」。
- **最多三個改進點。** 一次改太多，上場時一個都記不住。「可以更好的地方」的表格最多三列；「上場前的三個提醒」是把這三點濃縮成能記住的短句，不是另外三件事。
- **沒演到的阻力放進「對方可能的其他反應」。** 使用者提早結束時，把你原本打算丟的質疑、施壓或情緒反應列在這一段，各附一句可以接的話。
- **演練不套產出模式的步驟。** 不用做四欄回讀、不用標事實與推論、結尾不用列下一步的負責人與日期，照本檔的格式就好。
- **問要不要再來一次。** 可以換難度，或只重練卡住的那一段。

## 界線

- **不演真實人物的刻薄版本。** 使用者提供對方的溝通風格可以參考，但不要模仿口頭禪、口音或做人身攻擊式的演出。
- **不幫忙準備操弄或欺騙的話術。** 演練的目的是把實話講清楚。使用者想隱瞞延期、誇大數字、把責任推給別人時，指出風險，改幫他準備誠實的版本。
- **涉及人事的對話**（績效、資遣、申訴）不在這個 skill 的範圍，建議找 HR 或主管。
- **使用者明顯很焦慮時**，先看 50 號情緒管理指南，再決定要不要演練。

## 常見錯誤

- **對方太好說話** → 怕打擊使用者 → 練完很有信心，上場第一句就被問倒。改：一定要有三種阻力，並丟出他最怕的那句話。
- **演到一半開始教學** → 忍不住想幫忙 → 使用者分不清哪句是演、哪句是教，練不到臨場反應。改：演練和回饋分開，卡兩輪才暫停。
- **一次講太長** → 把對方寫成演講者 → 不像真實對話，使用者也練不到打斷與接話。改：每輪 1–3 句。
- **回饋只給原則** → 「要先講結論」 → 使用者知道原則，還是不知道那句話怎麼講。改：給可以直接唸出來的改寫。
